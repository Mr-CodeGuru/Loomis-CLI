## 1. Executive Summary

LoomisCLI is a fully operational, local-first Retrieval-Augmented Generation (RAG) code assistant that runs directly in the terminal. It indexes and searches repository code chunks using native vector similarity search, computes embeddings through an isolated Python background worker, and streams answers from a local large language model (`llama-server`) with explicit source citations.

All core functional components, integration pipelines, modular refactoring, and model prompt optimizations have been completed and verified end-to-end on Windows 11.

## 2. Architecture & Design Decisions

### 2.1 The Hybrid Dual-Runtime Architecture
```
┌────────────────────────────────────────────────────────────┐
│                    LoomisCLI Terminal REPL                 │
│              (src/main.rs, src/cli/session.rs)             │
└─────────────┬───────────────────────────────┬──────────────┘
              │                               │
       (Vector Search)               (JSON-Lines IPC)
              │                               │
              ▼                               ▼
┌───────────────────────────┐   ┌───────────────────────────┐
│     LanceDB VectorStore   │   │   Python Sidecar Worker   │
│       (src/db/store.rs)   │   │    (sidecar/embed.py)     │
│  70,163 Chunks in         │   │  jina-embeddings-v2-base  │
│  dbe/lancedb/chunks.lance │   │  HF_HOME isolated cache   │
└─────────────┬─────────────┘   └───────────────────────────┘
              │
      (Retrieved Context)
              │
              ▼
┌────────────────────────────────────────────────────────────┐
│                  OpenAI-Compatible LLM Client              │
│                     (src/llm/client.rs)                    │
│                 Token-by-token SSE streaming               │
└─────────────────────────────┬──────────────────────────────┘
                              │ (HTTP POST /v1/chat/completions)
                              ▼
┌────────────────────────────────────────────────────────────┐
│          llama-server (Llama-3.2-1B-Instruct-Q8_0)         │
│               Local Inference on Port 8080                 │
└────────────────────────────────────────────────────────────┘
```

- **Embedding Inference**: Offloaded to a dedicated Python subprocess (`sidecar/embed.py`) running `jinaai/jina-embeddings-v2-base-code` (768 dimensions). This eliminated custom C++/linker issues (`lld-link`) while keeping Rust fast and lean.
- **IPC Protocol**: Line-buffered JSON-lines over stdin/stdout (`{"v": 1, "cmd": "embed", "text": "..."}`).
- **Vector Database**: Native LanceDB Rust crate (`0.38.0`) with pinned `arrow = "58.4.0"` and `parquet = "58.4.0"`, providing zero-copy vector search over 70,163 precomputed embeddings.
- **LLM Engine**: Local `llama-server` hosting `Llama-3.2-1B-Instruct-Q8_0.gguf` with Server-Sent Events (SSE) streaming.

## 3. Detailed Accomplishments & Milestones

### Milestone 1: Python Embedding Sidecar (`sidecar/embed.py`)
- Created a standalone, dependency-minimal Python worker script.
- Hardcoded `HF_HOME` directly to the project's `models/` directory strictly before importing `transformers`, preventing stray downloads to `%USERPROFILE%\.cache`.
- Configured line-buffered UTF-8 stdin/stdout handling.
- Implemented protocol version checking (`v: 1`), health ping (`cmd: ping`), and single/batch text embedding (`cmd: embed`).

### Milestone 2: Rust IPC Manager with Crash Recovery (`src/sidecar/`)
- Built `SidecarClient` in `src/sidecar/client.rs` using `tokio::process::Command` with piped stdio.
- Implemented automated Python environment resolution in `src/sidecar/process.rs` (checking `.venv/Scripts/python.exe`, `VIRTUAL_ENV`, or system Python).
- Added handshake timeout and response validation.
- Built **automatic crash detection & transparent restart**: if the Python sidecar process terminates unexpectedly, `SidecarClient` automatically respawns the child process and retries the pending embedding query without user interruption.
- Verified 100% reliability via `examples/testSidecarIpc.rs`.

### Milestone 3: LanceDB Native Vector Storage (`src/db/`)
- Resolved Arrow and Parquet dependency version locks (`58.4.0`) matching LanceDB's internal types.
- Implemented `VectorStore` in `src/db/store.rs` with automatic schema detection:
  - If `dbe/lancedb/chunks.lance` exists, it connects immediately.
  - If the database table is absent, it reads `dbe/embeddings.parquet` and builds the native LanceDB table on the fly.
- Verified on-disk persistence across isolated runs (all 70,163 rows preserved and instantly reopened).

### Milestone 4: Semantic Retrieval Pipeline
- Integrated query embedding and LanceDB vector search into an end-to-end pipeline (`examples/testRetrievalPipeline.rs`).
- Verified that arbitrary natural language questions accurately rank relevant codebase functions (e.g., retrieving `mkmd5sum`, `getmd5sum`, `md5sum` for hashing questions).

### Milestone 5: Streaming LLM Client (`src/llm/`)
- Built `LlmClient` in `src/llm/client.rs` utilizing `reqwest` and `futures-util`.
- Developed a robust Server-Sent Events (SSE) byte-stream parser that extracts streaming token deltas (`choices[0].delta.content`) in real-time.
- Implemented `test_connection()` pre-flight check to verify server availability before launching the interactive loop.

### Milestone 6: Interactive Terminal REPL & Config (`src/cli/`)
- Created interactive shell session (`src/cli/session.rs`) featuring:
  - First-run configuration prompt saving endpoint and model preferences to `%USERPROFILE%\.loomiscli\config.json`.
  - Clean startup banner with active endpoint and chunk count.
  - Slash command router (`src/cli/commands.rs`): `/help`, `/stats`, `/config`, `/clear`, `/exit`.
  - Visual status updates: query embedding indicator, LanceDB snippet counter, and source citation breakdown (`[1] path (function) [dist: xx.xx]`).

### Milestone 8: Directory Rename & Exclusion Hardening (`dbe/`)
- Renamed root data directory from `db/` to `dbe/` (**D**ata **B**ase **E**mbeddings) to permanently prevent path collisions with `src/db/`.
- Updated `.gitignore` with anchored paths (`/dbe/`, `/models/`, `/target/`, `/.venv/`) and whitelisted source files (`!/src/**`).
- Hardened `scripts/tree.*` and `scripts/init-structure.*` to ensure source files are never excluded, while collapsing `dbe/` and `models/` placeholders.

### Milestone 9: Small-Model Prompt Engineering & Refusal Mitigation
- **Diagnosed the Refusal Bug**: Llama-3.2-1B (Q8_0) was returning *"I can't answer that."* due to:
  1. Negative framing in the system prompt (*"If the snippets do not contain enough information... acknowledge that clearly"*).
  2. The user query was placed at the bottom after large code blocks.
  3. Missing temperature/sampling controls.
  4. Ephemeral chat history storing prior refusals, causing subsequent turns to repeat the refusal.
- **Implemented Fixes**:
  - Rewrote system prompt with positive, constructive framing.
  - Positioned `User Question:` at the top of the prompt payload before code snippets.
  - Added per-snippet character truncation (1,500 chars) to prevent context-window overflow.
  - Added sampling parameters (`temperature: 0.2`, `max_tokens: 1024`).
  - Implemented history sanitization (filtering out refusals) and windowing (capping to the 2 most recent conversation turns).
- **Result**: Immediate, high-quality, fully cited code explanations generated and streamed without refusals.

## 5. How to Run

1. **Terminal 1 — Launch Local LLM Server**:
   ```powershell
   llama-server -m models\Llama-3.2-1B-Instruct-Q8_0.gguf -c 4096 --port 8080
   ```

2. **Terminal 2 — Launch LoomisCLI**:
   ```powershell
   cargo run
   ```
   *(or run the compiled binary directly: `.\target\debug\loomiscli.exe`)*
