## 1. Executive Summary

LoomisCLI has advanced from its initial baseline into a robust, stabilized, local-first RAG code assistant. Operating entirely on local hardware (macOS Apple Silicon & Windows 11), the system indexes 70,163 code chunks with zero-copy vector search via native LanceDB, runs an isolated Python sidecar for Jina code embeddings (`jinaai/jina-embeddings-v2-base-code`), and interfaces with local `llama-server` (`Llama-3.2-1B-Instruct-Q8_0`).

Over the `Nightly` stabilization cycle (`v1.0.0` through `v1.1.6`), we resolved critical retrieval grounding gaps, eliminated hallucinations, established pure LLM semantic intent gating, introduced ephemeral in-memory conversation history, split release vs nightly repository snapshot tooling, and implemented a real-time streaming syntax-highlighted code block formatter with Dark Modern / Monokai styling.

## 3. Major Accomplishments & Stabilization Milestones

### Milestone 1: Retrieved Snippet Grounding & Prompt Assembly (`v1.0.0`)
- Diagnosed prompt assembly failure where LanceDB chunks were retrieved but omitted from the generation prompt.
- Restructured `build_rag_messages()` in [`src/llm/prompt.rs`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/src/llm/prompt.rs) to wrap each retrieved chunk in dedicated markdown fences with file path, symbol name, and language tag.
- Placed user query at the top of the prompt to prevent small models (`1B`) from losing instruction focus after reading long code blocks.

### Milestone 2: Anti-Hallucination & Strict Import Minimization (`v1.0.1`)
- Eliminated dead/unused imports in model output by adding strict negative constraints.
- Bound model explanations exclusively to the code actually generated, requiring explicit citations of the adapted snippet file path and symbol.
- Verified on Part B test queries (`runQuestionSuite.rs`).

### Milestone 3: Generation Quality & Token Window Expansion (`v1.0.2`)
- Expanded generation limit (`max_tokens: 1024 -> 1536`), preventing mid-block code truncations during complex multi-function implementations.
- Established structured question test suite (`QTest/TQ1v1.0.2.md`) to evaluate retrieval mechanics and code generation separately.

### Milestone 4: Tooling & Script Separation (Base vs Nightly)
- Separated repository structure generators and initializers to guarantee clean development:
  - **Base Project Tools**: [`scripts/tree.sh`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/scripts/tree.sh), [`scripts/tree.ps1`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/scripts/tree.ps1), [`scripts/init-structure.sh`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/scripts/init-structure.sh), [`scripts/init-structure.ps1`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/scripts/init-structure.ps1) generate and manage [`STRUCTURE.txt`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/STRUCTURE.txt), strictly excluding `Nightly/` and all nightly artifacts.
  - **Nightly Development Tools**: [`scripts/nightly-tree.sh`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/scripts/nightly-tree.sh), [`scripts/nightly-tree.ps1`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/scripts/nightly-tree.ps1), [`scripts/nightly-init-structure.sh`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/scripts/nightly-init-structure.sh), [`scripts/nightly-init-structure.ps1`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/scripts/nightly-init-structure.ps1) maintain the full snapshot in [`NightStructure.txt`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/NightStructure.txt) and [`Nightly/NightStructure.txt`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/Nightly/NightStructure.txt).

### Milestone 5: Ephemeral In-Memory Session History (`v1.1.4`)
- Implemented multi-turn conversational memory on `ReplSession`:
  - **Strictly In-Memory**: Maintained as `Vec<ChatMessage>` for the process lifetime. Completely dropped on exit, preserving the zero-disk footprint principle.
  - **Adaptive Budgeting**:
    - `Chat`: Retains up to 10 messages (5 turns), capped at 4,000 characters.
    - `Code`: Retains up to 6 messages (3 turns), capped at 1,500 characters, safeguarding context budget for top-K code snippets.
  - Refined system instruction to eliminate confusion where the small model treated the system prompt as the user's prompt when answering meta-queries like *"what was my last prompt to you?"*.

### Milestone 6: Pure LLM Intent Routing & Regression Resolution (`v1.1.5`)
- Addressed regression where naive substring keyword matching (`is_explicit_code_request`) caused unprompted code dumping on conceptual questions containing code words (e.g. *"explain how a checksum works"*).
- **Completely removed all keyword/substring matching heuristics**.
- Implemented a pure semantic LLM classifier in [`LlmClient::classify_code_intent()`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/src/llm/client.rs) using few-shot classification prompts.
- Enforced strict conditional RAG flow:
  - If `CHAT`: Vector search bypassed $\rightarrow$ Direct concise conversational response.
  - If `CODE`: LanceDB search runs $\rightarrow$ Grounded code generation citing repository chunks.
- Achieved **18/18 (100%) accuracy** across the test phrasing matrix.

### Milestone 7: Real-Time Streaming Code Formatter & Monokai Theme (`v1.1.6`)
- Developed [`StreamingCodeFormatter`](file:///Users/aman/Desktop/EvaProjects/Loomis/CLI/LoomisCLI/src/cli/formatter.rs) for live token-by-token terminal rendering.
- **Framed Box Boundaries**:
  - Automatically identifies opening fences (` ```<lang> `) and renders top header with language tag:
    `╭─── [python] ──────────────────────────────────────────`
  - Prefixes each code line with left margin border (`│ `).
  - Renders bottom border upon closing fence (`╰───...`).
- **Dark Modern / Monokai Syntax Highlighting**:
  - Highlights declarations, imports, control flow, strings, numbers, booleans, function definitions/calls, and comments using standard ANSI escape codes.
- **Clean Context Guarantee**: Formatter outputs styled text directly to terminal stdout while returning raw markdown to `self.history`, ensuring multi-turn context remains unpolluted by terminal escape sequences.
